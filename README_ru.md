# Scar

[English](README.md) · **Русский**

**Каждый баг оставляет защиту.**

Scar добавляет проверку по накопленному каталогу классов ошибок в разработку с AI-агентами: SDD + TDD + верификация. Один плагин содержит скилл, хуки жизненного цикла, исполняемые проверки и постоянный личный каталог. Работает в обычной папке проекта: Git, CI, база данных и платные API моделей не обязательны.

## Установка в Codex

Нужен Node.js 20+. Зависимости уже включены в плагин: запускать `npm install` или поднимать отдельный сервер не нужно.

```text
codex plugin marketplace add VladyTipler/Scar
codex plugin add scar@scar-marketplace
```

Откройте новый чат. Один раз просмотрите и разрешите четыре командных хука Scar в интерфейсе Hooks в Codex. Установка сама по себе не разрешает выполнение хуков. Без этого скилл и инструменты доступны, но автоматический контроль завершения задачи не работает. Настраивать каждый проект, заводить Git-репозиторий, CI или базу данных не требуется.

Проверено с Codex 0.156.1. Плагин использует `.codex-plugin/plugin.json` и `.mcp.json`: эта версия Codex пропускает хуки плагинов с новым корневым форматом `plugin.json`. Пример будущего формата сохранён в `docs/` и не используется для запуска. [Исходный код загрузчика](https://github.com/openai/codex/blob/rust-v0.156.1/codex-rs/core-plugins/src/loader.rs#L950), [документация по разрешению хуков](https://learn.chatgpt.com/docs/hooks).

Для MCP в Codex используется относительный путь к сборке и `cwd` относительно плагина: этот загрузчик не подставляет переменные пути хуков в аргументы MCP. Совместимый манифест Claude использует синтаксис путей своего хоста. [Исходный код загрузки MCP](https://github.com/openai/codex/blob/rust-v0.156.1/codex-rs/codex-mcp/src/plugin_config.rs).

## Установка в ZCode

Нужен Node.js 20+, доступный процессу ZCode. Зависимости включены в плагин: `npm install` и отдельный сервер не нужны.

1. Откройте **Plugin Marketplace → Add → Add Plugin Marketplace** и введите `VladyTipler/Scar` или Git URL этого репозитория.
2. В **Personal → scar-marketplace** откройте **Scar** и нажмите **Install**. Для уже установленного плагина обновите источник маркетплейса и обновите Scar до **0.1.1**.
3. Создайте новую задачу и выберите скилл **scar**. Манифест объявляет один скилл, MCP-сервер Scar с десятью инструментами и те же четыре авторских хука, что для Codex/Claude: `SessionStart`, `UserPromptSubmit`, `Stop`, `SessionEnd`.

ZCode выбирает `.zcode-plugin/plugin.json`, который использует общий `hooks/native.json` без изменения жизненного цикла Scar. Stop проверяет завершение задачи; служебную запись сессии удаляет только SessionEnd. Завершение ответа не означает завершения сессии, а SessionEnd не отменяет контроль незавершённой задачи.

**В ZCode 0.16.9 совместимость неполная:** хост не распознаёт и не вызывает SessionEnd. Объявить четыре хука — не значит обеспечить выполнение всех четырёх; нужна поддержка SessionEnd в самом ZCode. Обработчик Stop также не передаёт терминальный неблокирующий `systemMessage` Scar в контекст. Плагин не обходит эти ограничения переносом очистки в Stop или изменением авторского контракта ответа.

MCP и скилл можно проверить отдельно, но установка, валидация манифеста и прямой запуск процессов хуков не доказывают поддержку полного жизненного цикла. Границы результатов — в [отчёте о верификации](docs/verification.md).

## Обычный рабочий процесс

Сообщите агенту, что нужно разработать. Scar дополняет ваши инструкции для SDD и TDD, включая superpowers.

1. **Перед кодом — `scar_prepare`.** Движок выбирает применимые классы ошибок и находит существующие команды проверок проекта. Недостающие проверки поведения и интеграций агент добавляет сам.
2. **Разработка — SDD + TDD.** Обработка каталога и запуск детекторов выполняются программным кодом, без вызовов модели.
3. **Проверка — `scar_verify`.** Запускаются все применимые защиты и команды проекта. Отсутствие проверок, ошибки разбора файлов, пробелы в покрытии, таймауты, проваленные проверки и устаревшие результаты не позволяют завершить верификацию успешно.
4. **Обучение — `scar_learn`.** Найдя значимый дефект, агент выделяет его класс, ищет аналогичные случаи и сохраняет исполняемый детектор. Примеры исходной ошибки, независимого варианта ошибки и корректного кода должны подтвердить заявленную область защиты.
5. **Завершение — `scar_review` → `scar_finish`.** Агент фиксирует результат обучения, затем повторно запускает верификацию. Разрешённый хук Stop сверяет результаты с текущими файлами, контрактом и каталогом, не перезапуская тесты. После трёх автоматических запросов на исправление дальнейшее завершение останавливается с явным статусом `INCOMPLETE`.

Хуки начала сеанса и отправки запроса читают только небольшие файлы состояния Scar и сохранённые подсказки. Они не обходят исходники, не разбирают код, не запускают проверки и не обращаются к удалённому каталогу. `scar_prepare` обновляет подсказки и включает контроль завершения программной задачи; каждый вызов создаёт новую версию задачи. После успешного Stop этот контроль закрывается, чтобы обычный разговор не запускал его снова. **Если агент пропустил подготовку, хуки без обхода исходников не обнаружат изменения кода.** Скилл требует подготовки перед каждой программной задачей. Удаление результатов из папки проекта не отменяет уже включённый контроль.

Внутренние бюджеты работы хуков: 1 секунда для начала сеанса и отправки запроса, 2 секунды для Stop, 0,5 секунды для SessionEnd. Управляющий процесс допускает ещё секунду на завершение рабочего процесса и его дочерних процессов. Это ограничения работы, а не обещание конкретной длительности запуска. Если за отведённое время нельзя подтвердить актуальность результатов, Stop возвращает `INCOMPLETE`: он не принимает сохранённый `READY` без проверки и не отправляет верификацию в фон. Подробнее — [устройство хуков](docs/hook-latency.md).

При расширении класса сохраняются его ID, ранее защищённые расширения файлов и проверочные примеры прошлых версий. Личный каталог хранится вне установки плагина: `<user-home>/.scar/catalog.json`. Он переживает обновления плагина и применяется в разных проектах. В папке проекта `.scar/` находятся сгенерированные контракты и полные отчёты. Личный каталог и отчёты не публикуются в репозитории плагина.

## Размер каталога и расход токенов

Подготовка возвращает первую страницу из восьми коротких подсказок. **Восемь — не ограничение количества проверок.** Описание задачи и пути файлов помогают ранжировать подсказки. `scar_context` возвращает дополнительные страницы, не меняя контракт выполнения. `scar_catalog` позволяет искать классы, читать каталог постранично или получать один класс по ID; код детектора и проверочные примеры доступны отдельными фрагментами по 4000 символов. Все защиты, применимые по расширениям файлов, выполняются, даже если их описания не попали в контекст модели.

Инструменты верификации возвращают ограниченную сводку и полные счётчики. `scar_details` позволяет читать замечания постранично и получать короткие фрагменты логов. Полные результаты остаются на диске. Запуск проверок расходует процессорное время, но Scar сам не вызывает LLM или API моделей. Разбор ошибок агентом, написание детекторов и исправление кода по-прежнему расходуют токены.

## Что проверяется сейчас

Встроенные проверки по AST находят пустые блоки `catch`, асинхронные обработчики `forEach` и асинхронные функции-исполнители `Promise` в JS/TS/JSX/TSX и скриптах Vue. Грамматика JavaScript проверяется отдельно от TypeScript. Внешние скрипты Vue и неподдерживаемые кодировки отмечаются как пробелы в покрытии.

Scar находит существующие npm-команды тестирования, проверки типов, линтинга и сборки, а также проверки Go, Cargo и pytest. Другие инструменты и защиту для конкретных языков агент добавляет через исполняемые проверки проекта и доказанные личные детекторы. При отсутствии проверок результат — `INCOMPLETE`. Статус `READY` означает, что заявленные проверки прошли на актуальных файлах, контракте и каталоге; он не доказывает отсутствие всех возможных багов. Пользовательские детекторы — доверенный исполняемый код с ограничениями времени и объёма вывода, а не изолированная песочница безопасности.

## Общий каталог на разных машинах

Необязательный SSH-транспорт позволяет использовать один личный каталог на разных машинах без отдельного сервиса или базы данных. Агент или администратор один раз указывает доверенный сервер, путь к движку и каталог хранения в личном `connection.json`; проекты настраивать не нужно. Ошибка настроенного транспорта блокирует верификацию, а не подменяет общий каталог пустым локальным. Локальный режим работает без сети. Данные транспорта обрабатываются кодом и не загружаются целиком в контекст модели.

## Разработка плагина и подтверждение результатов

Следующие команды нужны разработчикам самого Scar, а не пользователям установленного плагина:

```text
npm ci
npm run build
npm test
npm run test:feature
```

На Windows запускайте npm/npx через PowerShell. Тесты пересекают реальные границы файловой системы, процессов и MCP. Они проверяют обучение без Git, повторное использование знаний в новом процессе, устаревшие отчёты, ограничения контекста, сохранение защиты прошлых версий, нативные события хуков и запуск отдельных сборок без `node_modules`. Ранее проверки выполнялись на Windows и Linux; ревизия совместимости с ZCode также проверяется на macOS, включая отдельные сборки и реальные процессы MCP и хуков. Windows-тесты на macOS пропускаются; это не подтверждение выполнения реальной задачи в ZCode. Точные результаты и границы активации — в [отчёте о верификации](docs/verification.md). Подробности запуска и Windows-ограничений — в [инструкции по эксплуатации](skills/scar/references/operations.md).

Лицензия исходного кода ещё не выбрана. Лицензии включённых зависимостей сохранены в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
